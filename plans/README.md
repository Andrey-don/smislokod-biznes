# plans/ — технические планы реализации

## Что это

Место для технических планов реализации функций. Каждый план — отдельный файл.

## Правила

1. **Один план = одна функция.** Если план уже есть — работаем с ним, не создаём новый.
2. **Формат имени файла:** `YYYY-MM-DD-название-функции.md` (текущий год, месяц, день).
3. **Каждый план делится на фазы.** У каждой фазы статус `[ ]` (не начата), `[WIP]` (в работе) или `[x]` (готово).
4. **В конце плана — итоговый блок:** реализован целиком или нет, что осталось, ссылки на коммиты.
5. **Любой агент, работающий с планом, обязан его актуализировать** после каждой сессии.
6. **Микрофича — без плана.** Граница: если задача больше часа работы — нужен план.

## Цикл работы с планом (три чата)

1. **Чат 1** — формирует первичный план (цель, гипотезы, технические решения, последовательность).
2. **Чат 2** — разбивает план на фазы с конкретными deliverable и критериями «сделано».
3. **Чат 3** — критикует каждую фазу: реализуемость, риски, конфликты, безопасность, соответствие бизнес-целям.
4. Только после прохождения всех трёх чатов — реализация.

## Зачем не plan mode

Plan mode живёт в одном контекстном окне. Большой план туда не влезет, агент забудет половину, токены сгорят. Внешний файл в `plans/` живёт вечно и доступен любому агенту в любой момент.
