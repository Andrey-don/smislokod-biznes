# План реализации шаблонного вайб-проекта (СмыслоКод)

> **Источник:** Инструкция «Спланируй свой проект» (День 2, СмыслоКод, май 2026)
> **Цель:** Создать шаблонный проект, который клонируется при старте новых проектов
> **Время:** ~3-4 часа (большую часть делает Claude Code, ты управляешь голосом)

---

| Файл | Назначение |
|------|-----------|

## Этап 1. Фундамент: звук, безопасность, авто-память (~30 мин)

**Шаг 1.1 — Звуковые уведомления (hooks)**

Цель: слышать пик из другой комнаты, когда Claude завершил задачу.

Промт для Claude Code:
```
Настрой мне в .claude/settings.json звуковые уведомления (hooks):
1. Звук при завершении задачи (Stop hook)
2. Звук при запросе разрешения (Notification hook)
Используй системный звук операционной системы.
Покажи итоговый файл .claude/settings.json.
```

**Шаг 1.2 — Базовые правила безопасности**

Промт:
```
Настрой в .claude/settings.json правила безопасности. ЗАПРЕТИ:
1. rm -rf и массовое удаление без подтверждения
2. export + curl — отправку переменных окружения наружу
3. Чтение файлов .env и файлов с секретами
4. wget с переменными — отправку данных наружу
Покажи итоговый settings.json с объяснением каждого правила.
```

**Шаг 1.3 — Авто-память**

Глобальная авто-память `~/.claude/memory/` работает автоматически. Когда говоришь «не делай X» — Claude сам записывает правило.

├── mastery/
└── reference/
INDEX.md заполни как карту. Остальные — заглушки.

**Шаг 2.2 — Голосовое интервью для наполнения**

Промт-интервью (запускать отдельным диалогом):
```
Ты - интервьюер. Соберёшь мой профиль для AI-Clone.

- Вопросы по одному.
- К каждому вопросу предлагай 3-4 варианта ответа.
- «Не знаю» → предложи вариант, спроси согласен ли.
- Не больше 5-7 вопросов на блок.
Начинай с блока identity. Всегда отвечай на русском.
```

**Шаг 2.3 — Папка feedback/ (правила через ошибки)**

Не заполнять вручную. Работает так:
- Claude предложил неправильное решение
- Говоришь: «не так, потому что X»
- Добавляешь: «запиши правилом в ai-clone/feedback/ в формате: Правило / Почему / Как применить»

**Шаг 4.2 — Голосовое интервью бизнес-контекста**

> ⚠️ Это самый ценный промт во всей инструкции. Не пропускай.
> Скилл сохранён в `.claude/skills/business-interview/SKILL.md`.
> Запускать в **новом диалоге** с Claude Code.

Скопируй целиком и запусти:

```
Ты помогаешь мне создать папку business/ для моего проекта.

МОЯ ИДЕЯ В ОДНОМ ПРЕДЛОЖЕНИИ:
[ВПИШИ СЮДА СВОЮ ИДЕЮ]

ДЕЙСТВУЙ ПО БЛОКАМ:

1. products    - что я продаю, какие тарифы, цены
2. audience    - для кого, портрет, боли, путь покупки
3. economics   - выручка, расходы, юнит-экономика
4. marketing   - каналы, воронка, конкуренты, контент-стратегия
5. goals       - годовая, квартальная, месячная цели

ПРАВИЛА ИНТЕРВЬЮ:
- Иди ПО ОДНОМУ блоку за раз. Закончил блок — записал файлы — перешёл к следующему.
- В каждом блоке задавай вопросы ПО ОДНОМУ.
- К КАЖДОМУ вопросу сразу предлагай 3-4 варианта ответа на основе моей идеи. Я выберу номер,
  или скажу «свой вариант: ...», или скажу «не знаю».
- Если я говорю «не знаю» — предложи свой вариант, который ты считаешь лучшим для моей идеи,
  и спроси, согласен ли я.
- Если я даю короткий ответ — задай 1-2 уточняющих вопроса с вариантами.
- Не задавай больше 5-7 вопросов на блок. Не превращай это в допрос.

ПОСЛЕ КАЖДОГО БЛОКА сразу записывай результат в файлы внутри соответствующей подпапки:
- products:   products/overview.md, products/pricing.md
- audience:   audience/avatar.md, audience/objections.md, audience/journey.md
- economics:  economics/unit-economics.md, economics/revenue.md, economics/costs.md
- marketing:  marketing/channels.md, marketing/funnel.md, marketing/content.md, marketing/competitors.md
- goals:      goals/annual.md, goals/quarterly.md, goals/monthly.md

Если у меня в блоке мало данных — создай файл с заголовком и пометкой «заполнить позже»,
но не пропускай.

После всех пяти блоков обнови business/INDEX.md так, чтобы он содержал:
- название проекта одной строкой
- одно предложение «о чём проект»
- список всех файлов с одной строкой описания каждого
- правило: «при работе читай только нужный файл, не загружай всё сразу»

В самом конце покажи мне дерево созданной business/ и спроси, что добавить или изменить.

ВАЖНО:
- Я говорю голосом, не печатаю.
- Не пиши код, не делай ничего, кроме создания файлов и интервью.
- Не задавай все вопросы сразу — только по одному.

Начинай с блока products.

Всегда отвечай на русском.
```

Что получишь: через 40-60 минут разговора — полностью заполненная папка `business/` под твою идею.

**Шаг 4.5 — Как поддерживать `business/` живым**

> Скилл сохранён в `.claude/skills/business-review/SKILL.md`.
> Это не разовый шаг, а постоянная привычка.

Мозг растёт, пока в него докладывают. Цикл, который работает:

- **В течение недели** — скидываешь голосом «по горячему» в notes: вопросы, возражения, идеи.
- **В конце недели** — один промт: «вот накопленное, разбери и обнови файлы в business/». Claude сам найдёт, куда положить.
- **После значимого события** — «проанализируй вопросы из чата эфира и обнови `audience/objections.md`, `audience/avatar.md`».

**Главное правило:** валидируй своей головой. Иначе ИИ будет запихивать ерунду наравне с золотом. Лень валидировать — получишь мусор.

**Промт 1 — разбор лендинга** (если уже есть готовый сайт):
```
У меня уже есть рабочий лендинг по адресу [ВСТАВЬ URL ИЛИ ПУТЬ К index.html].
Открой, прочитай целиком (hero, услуги, оффер, цены, отзывы, FAQ).
Вытащи ключевые смыслы и разложи по папкам business/:
- продукт, тарифы, цены → products/
- аудитория, боли, путь → audience/
- оффер, копи-банк, формулировки → assets/copy-bank.md
- конкурентные преимущества → marketing/competitors.md
После каждой папки — краткий отчёт: что нашёл и куда положил.
Не выдумывай данные — если на лендинге нет, оставь «заполнить интервью-промтом».
Всегда отвечай на русском.
```

**Промт 2 — разбор зум-звонка / встречи / эфира:**
```
У меня лежит транскрипция встречи в файле [путь к файлу].
Прочитай целиком. Вытащи 5-7 ключевых идей / решений / инсайтов.
По каждой идее определи, куда она относится:
- аудитория → business/audience/
- продукт → business/products/
- принцип переговоров → ai-clone/principles/business.md
- выученный урок → ai-clone/feedback/
Покажи предложения: «вот эту идею предлагаю положить сюда» — я подтверждаю.
После подтверждения — запиши в нужные файлы.
Всегда отвечай на русском.
```

## Этап 5. CLAUDE.md + plans/ + retrospectives/ (~30 мин)

**Шаг 5.1 — CLAUDE.md (трудовой договор агента)**

Порядок:

2. Поверх наложить шаблон из инструкции (раздел «Шаблон CLAUDE.md»)

- 6 правил: лимит строк / отчёт в конце диалога / коммит после задачи / bulletproof / сверка с business/ / безопасность

```
Создай plans/README.md:

3. Фазы с чекбоксами [ ] / [x]
4. Итоговый блок в конце

## Этап 7. Промтинг и работа с агентом (~30 мин)

**6 шагов вайб-кодинга:**
1. Инструкция в `instructions.md` (голосом)
2. Уточняющие вопросы в Plan Mode (`Shift+Tab`)
3. Формирование CLAUDE.md (стек, структура)
4. Реализация в **новом диалоге** (Bypass Permissions)
5. Итерации голосом + скриншоты
6. Крупные фичи — чанками, каждый в отдельном диалоге

**Стресс-тест «10 причин обосраться»:**
```
У меня есть CLAUDE.md, ai-clone/, business/, mastery/.
Найди 10 причин, из-за которых мы провалимся:
- двусмысленности в CLAUDE.md
- пробелы в business/
- чего не хватает в ai-clone/
- противоречия в бизнес-логике
- переоценка объёма одного дня
В конце: список конкретных правок по файлам.
```

**6 правил выживания:**
1. Один чат = одна задача
2. Контекст ≤ 60% → `/compact`
3. Ничего руками — только через Claude
4. Ошибки чинить в том же чате
5. Долго думает — жди, не перезапускай
6. Большие фичи → `plans/` + `retrospectives/`

## Этап 11. Триггеры — агент 24/7 (~20 мин)

Триггеры = cron/webhook-задачи, которые запускают агента по расписанию.

**Пример:**
- 7:00 → агент собирает метрики → отправляет отчёт в Telegram
- Новый коммит в GitHub → агент запускает bulletproof-тесты

```
Настрой триггер: каждый день в 7:00 утра агент читает

## Важные ограничения и правила

| Правило | Почему |
|---------|-------|
| CLAUDE.md ≤ 200 строк | Иначе контекст переполняется |
| 1 задача = 1 диалог | Контекст засоряется историей |
| Контекст ≤ 60% | При 70%+ агент деградирует |
| plans/ а не Plan Mode | Plan Mode теряется при закрытии |
| Новый диалог для реализации | Контекст планирования мешает |
| Bulletproof перед деплоем | Обязательное тестирование |
| Не хардкодить цифры | Используй LIVE-маркеры |
| Не класть ПДн в business/ | Риск утечки |
| Запреты в settings.json | Агент не может навредить физически |
