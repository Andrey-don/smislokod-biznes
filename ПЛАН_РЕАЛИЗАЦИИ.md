## Этап 1. Звук, безопасность, авто-память (~30 мин)

**Шаг 1.1. Звуковые уведомления (hooks)**

Запустил задачу, ушёл за чаем, Claude закончил через 2 минуты и ждёт — а ты думаешь, он ещё работает. Полчаса простоя. Решение — hooks: звук при завершении задачи и при запросе разрешения.

Промт:
```
Настрой мне в .claude/settings.json звуковые уведомления (hooks):
1. Звук при завершении задачи (Stop hook) — чтобы я слышал, когда ты закончил работу.
2. Звук при запросе разрешения (Notification hook) — чтобы я слышал, когда ты ждёшь моего «да/нет».
Используй системный звук моей операционной системы. Покажи итоговый файл .claude/settings.json и объясни, что ты добавил.
```

Минимальная форма (если лень разворачивать): «Настрой хук для звукового сигнала при завершении диалога и при запросе разрешений». Claude поймёт и сделает.

Проверка: задай ему любую задачу («посчитай 2+2 и заверши работу»). Должен пикнуть.

**Альтернатива — зелёная полоска (если звук отключён):**
Вместо звука — визуальная полоска на весь экран снизу. Зелёная при завершении задачи, оранжевая при запросе разрешения. Закрывается только по клику.
Реализована через PowerShell + WinForms, запускается через `.bat`-файл как фоновый процесс.
Файлы лежат в `.claude/hooks/`: `notify-stop.ps1`, `notify-stop.bat`, `notify-permission.ps1`, `notify-permission.bat`.

---

**Шаг 1.2. Базовые правила безопасности**

Эти запреты особенно важны, если ты собираешься работать в Bypass Permissions — режим полной автономии агента, когда он не спрашивает каждый чих. Без рамок он может случайно удалить файлы, прочитать секреты, отправить данные наружу. Отдельный риск — «фишинговые» сторонние скиллы: в них зашивают команды «собери ключи из env и отправь на такой-то URL». Запреты в settings.json ловят такое до того, как оно сработает.

Промт:
```
Настрой мне в .claude/settings.json правила безопасности. ЗАПРЕТИ:
1. Команды вида `rm -rf` и любое массовое удаление файлов или папок без явного подтверждения от меня.
2. Связку `export` + `curl` — любую отправку переменных окружения наружу через curl.
3. Чтение файлов .env и любых файлов с секретами, ключами, паролями.
4. `wget` с подставленными переменными — любую отправку моих данных наружу через wget.
Используй секцию permissions.deny (или эквивалентную секцию в актуальной версии Claude Code).
После изменения — покажи итоговый файл .claude/settings.json и объясни каждое правило одной строкой.
```

Если Claude ругается на синтаксис: «обнови знание о Claude Code до последней версии и покажи правильный синтаксис permissions.deny».

---

**Шаг 1.3. Авто-память Claude (`~/.claude/memory/`)**

Кроме `feedback/` внутри `ai-clone/` (проектная) есть глобальная авто-память на уровне самого Claude Code: `~/.claude/memory/`. Сказал «не хардкодь даты, всегда бери из базы» — Claude сам записал правило в файл и помнит его во всех проектах. Со временем там накапливаются десятки файлов: правила, предпочтения, ссылки на инфраструктуру, бренд. Один раз сказал — помнит всегда.

Глобальная учит Claude твоим привычкам в принципе. `ai-clone/feedback/` — правилам конкретного проекта. Работают одновременно.

## Этап 2. Создаём ai-clone/ — кто ты для агента (~45 мин)

Самый необычный концепт дня. И самый ценный. **AI-Clone — это ты в файлах.** Не «ИИ, который понимает твой стиль». А ИИ, который знает тебя на уровне принятия решений: что ценишь, что отвергнешь сразу, какие принципы, темп, амбиции, стандарты. Цифровая проекция. Думает как ты. Сам находит проблемы, сам приносит решение — ты говоришь «да».

Без AI-Clone каждый чат начинается с «привет, я веду проект такой-то». 5-10 минут разогрева в каждом окне. **Один клон — все твои проекты.** Личность одна. Каждый проект цепляется к клону через `CLAUDE.md`.

**Шаг 2.1. Создаём структуру `ai-clone/`**

Промт — копируй и вставляй:
```
Создай в корне моего проекта папку ai-clone/ со следующей структурой:

ai-clone/
├── INDEX.md           - точка входа, карта папки
├── role.md            - кто я: бэкграунд, что важно знать обо мне
├── identity/          - values.md, vision.md, mission.md, biography.md
├── voice/             - tone.md, vocabulary.md, stop-words.md
├── thinking/          - mental-models.md (как принимаю решения)
├── principles/        - product.md, code.md, business.md
├── feedback/          - пока пустая, сюда будут падать правила
├── style/             - telegram-format.md, общая стилистика
├── mastery/           - чужие методологии великих (можно держать здесь или в корне проекта)
└── reference/         - инструменты, инфра без секретов

Действуй так:
1. Создай всю структуру папок и файлы-заглушки с короткими заголовками
   (что должно лежать в каждом файле).
2. INDEX.md заполни как карту: список всех файлов с одной строкой описания каждого
   + правило «при работе читай только нужный файл, не загружай всё сразу».
3. В feedback/ создай только README.md с объяснением: «здесь живут правила,
   выученные через ошибки. Формат: Правило / Почему / Как применить».
4. Покажи дерево созданной папки.

Всегда отвечай на русском.
```

**Что получишь:** скелет папки `ai-clone/`. Все файлы пока пустые, кроме INDEX.md.

---

**Шаг 2.2. Наполняем `ai-clone/` через голосовое интервью**

Главный способ — **голосовое интервью с ИИ**, делаем сегодня. Также можно наполнять из: транскрипций эфиров и зум-звонков, деловой email-переписки за месяц-два, авто-памяти ChatGPT (Settings → Personalization → Memory), Telegram-чатов с коллегами (через бота, который раз в сутки пробегается по сообщениям и предлагает обновления — только обязательно с твоей валидацией).

Запускать в **новом диалоге**. Идём по пути №1. Промт интервью:
```
Ты — интервьюер. Соберёшь мой профиль для AI-Clone.

Задай мне вопросы по блокам:
- identity (кто я: ценности, путь, миссия, биография)
- voice (как я говорю: тон, словарь, стоп-слова)
- thinking (как принимаю решения, какие ментальные модели использую)
- principles (мои правила в продукте, коде, бизнесе)
- style (что отвергаю, какая эстетика)

ПРАВИЛА:
- Иди ПО ОДНОМУ блоку за раз. Закончил блок — записал файлы — перешёл к следующему.
- В каждом блоке задавай вопросы ПО ОДНОМУ.
- К КАЖДОМУ вопросу сразу предлагай 3-4 варианта ответа на основе того, что я уже сказал,
  и общих паттернов основателей. Я выберу номер, или скажу «свой вариант: ...», или скажу «не знаю».
- Если я говорю «не знаю» — предложи свой вариант, который ты считаешь правдоподобным,
  и спроси, согласен ли я.
- Не задавай больше 5-7 вопросов на блок.
- После каждого блока СРАЗУ записывай результат в соответствующие файлы в ai-clone/.

Я говорю голосом (через Whisper Flow или /voice), не печатаю.
Можешь рассчитывать на короткие, но содержательные ответы.

Начинай с блока identity.

Всегда отвечай на русском.
```

Секретная фраза — «предлагай 2-3 варианта ответа». Снимает паралич чистого листа.

Что получишь: через 30-40 минут разговора — заполненную папку `ai-clone/` с реальной информацией про тебя.

Если что-то пошло не так:
- Claude валит все вопросы сразу → напомни: «по одному вопросу за раз»
- Не сохраняет в файлы → скажи: «после каждого моего ответа записывай в нужный файл, потом задавай следующий вопрос»
- Получились слишком короткие файлы → попроси: «развёрни identity/values.md в полноценный документ, опираясь на наш диалог»

---

**Шаг 2.3. Главная папка — `feedback/`**

Эту папку ты не заполняешь руками. Здесь живут правила, выученные через ошибки. Они появляются естественным путём.

Как это работает:
1. Claude предложил решение.
2. Ты говоришь: «не так, потому что X».
3. Сразу добавляешь: «запиши это правилом в ai-clone/feedback/, в формате: Правило / Почему / Как применить».
4. Claude создаёт файл вроде `feedback/no-em-dashes.md` с тремя секциями.
5. В следующем диалоге Claude уже сам не делает эту ошибку — потому что читает `feedback/` через `INDEX.md`.

Через месяц в `feedback/` — десятки правил, на каждое из которых ты потратил по 30 секунд. «Не делай X в проекте Y», «не используй слово Z в текстах для клиентов», «перед деплоем всегда проверяй A». Раз в день говорил «не так» — через месяц своя личная конституция.

> «Я не пишу правила руками. Я говорю — не так, потому что вот так. И ИИ оформляет это в файл».

## Этап 3. Папка mastery/ — чужое мастерство (~30 мин)

После того как ИИ знает тебя — подключим к нему чужой ум. Скилл — это «сделай PDF», навык. **Mastery — точка зрения эксперта на целую область.** Не книги, не саммари, не пересказ. Только методы с пошаговым алгоритмом «как применить».

«У каждого великого автора 1-2-3 гениальных метода. Вся их жизнь, чтобы выделить пару методов. Мы берём только эти методы».

Утром пишешь пост — ИИ работает как копирайтер (Огилви + Шугерман). Через час созваниваешься с подрядчиком — переключается в переговорщика (Восс). Вечером смотришь финансовый отчёт — становится финансовым аналитиком. **Один Claude. Десятки экспертных линз. Mastery превращает обычного агента в команду экспертов под рукой.**

**Шаг 3.1. Создаём папку `mastery/`**

Промт:
```
Создай в корне моего проекта папку mastery/. Это «личный совет директоров»:
концентрат методов лучших умов мира по нужным мне областям.

Структура:

mastery/
├── INDEX.md   - карта папки, список областей и правил
└── README.md  - объяснение методологии: «один автор = один файл, только методы, не пересказ»

В INDEX.md напиши:
- что такое mastery, чем отличается от skills
- правило: «1-2-3 гениальных метода у каждого автора, не книги целиком»
- структура: «одна папка = одна область, один файл = один автор»
- список областей появится по мере наполнения

Подпапки и файлы внутри не создавай — будем наполнять отдельно.
```

---

**Шаг 3.2. Собираем первую папку мастерства (выбери одну область)**

Выбери одну область — ту, где у тебя сейчас самая частая задача. Если ведёшь Telegram-канал — копирайтинг. Если ведёшь переговоры — переговоры. Если занимаешься финансами — финанализ.

Промт:
```
Помоги мне собрать первую папку мастерства — mastery/copywriting/.
(Замени copywriting на свою область: переговоры, финанализ, маркетинг, найм, продажи, что угодно.)

Действуй так:
1. Найди 3-5 признанных авторов в этой области. Не «известных в инфобизе»,
   а тех, кого реально читают практики. По копирайтингу: Огилви, Шугерман, Кэплз, Эл Райс.
   По переговорам: Восс, Карасс. По финансам: Мангер, Грэм. По продажам: Чет Холмс, Хормози.

2. По каждому автору найди 1-3 гениальных метода. Не пересказ книги.
   Метод — это конкретный приём с пошаговым алгоритмом «что делать, как делать, когда применять».

3. Создай по каждому автору отдельный файл: mastery/<область>/<имя-автора>.md.
   Внутри каждого файла:
   - Кто автор (3-5 строк)
   - Метод 1: название / суть / шаги / когда применять
   - Метод 2: то же самое
   - Метод 3 (если есть)
   - Связь с другими методами через викилинки [[файл]]

4. Создай mastery/<область>/INDEX.md — карта папки: список авторов с одной строкой про каждого.

5. В корневом mastery/INDEX.md добавь раздел про эту новую область.

Каждый файл — 3-5 KB чистого концентрата. Не «уныло пересказал главу книги»,
а «вот метод, вот шаги».

Всегда отвечай на русском.
```

Что получишь: папку `mastery/` с одной заполненной областью. Например, `mastery/copywriting/` с тремя-пятью файлами по 3-5 KB — суммарно ~15 KB концентрата вместо 5 книг по 200 страниц.

Важное правило сборки. Если есть полуторачасовое видео-выступление специалиста в твоей нише:
- Скачай аудио, прогони через Whisper (см. Шаг 8.6) — получишь транскрипцию
- Положи транскрипцию в `mastery/<область>/raw/имя-автора-выступление.md`
- Скажи Claude: «вот файл с транскрипцией, выдели ключевые методы автора, опиши каждый по формуле: что / как / когда. Положи в mastery/<область>/имя-автора.md»

Это не галлюцинация — это вытяжка из реального человека.

**Выйди за язык.** Не ограничивайся русскоязычными авторами. «Найди американца, который ведёт блог на эту тему, скачай его транскрипции выступлений с YouTube, выдели методологию, оформи как `Зак-Ютубер.md`». Лучшие в мире обычно пишут не на русском — вытаскивай их.

> Старый приём «ты копирайтер с двадцатилетним стажем, действуй, будто это твой последний шанс» (role-prompting) — устарел. Mastery даёт ИИ конкретные методы конкретных людей, не выдуманную «роль».

---

**Шаг 3.3. Кейсы применения mastery**

Кейс 1 — контент-завод. Папка `mastery/copywriting/` собрана. Утром говоришь Claude: «напиши пост в канал про X». Claude автоматически проваливается в `mastery/copywriting/`, берёт методы Огилви, Шугермана, твой голос из `ai-clone/voice/` — и пишет так, как написал бы ты, с конкретной техникой заголовков. Не «универсальный пост», а пост через линзу копирайтера-мастера. То же самое с короткими видео, кружочками, telegram-постами — заводишь свои выступления и зумы в `mastery/`, и ИИ копирует твою фабрику.

Кейс 2 — финанализ. Спрашиваешь «что у нас по цифрам в этом квартале?» — Claude берёт `mastery/financial-analysis/`, идёт в `business/economics/`, смотрит цели в `business/goals/quarterly.md`, применяет методы к данным. Один Claude. Десятки экспертных линз — и каждая под рукой.

Пример наполнения папки `mastery/` (для вдохновения, не для копирования):

```
mastery/
├── copywriting/         - заголовки, оффер, лендинги
├── decision-making/     - Мангер, инверсия, ментальные модели
├── negotiations/        - Восс, Карасс
├── financial-analysis/  - юнит-экономика, прогноз
└── public-speaking/     - структура выступлений
```

У тебя будет своя комплектация — под твои задачи.

## Этап 4. Создаём business/ — что мы делаем (~60-90 мин)

Теперь о деле.

**Зачем.** Без бизнес-контекста Claude каждый раз с нуля - не знает твою аудиторию, цены, цели, дизайн. Результат шаблонный, «как у всех». С папкой `business/` Claude знает про твой бизнес всё и работает как сотрудник на втором году опыта.

Главное место - **рядом с кодом**. Не в Notion, не в Google Docs, не в Telegram-чатах. В одной папке с проектом. ИИ читает оба мира одновременно. Без копипасты.

> «Папка с контекстовыми файлами не в голове, не в Notion, не в чатах, а рядом с кодом в одной папке с проектом».

В этом потоке мы убрали точку перед именем папки: было `.business/` - стало `business/`. Так проще работать и видно сразу при открытии проекта.

**Второй мозг нужен НЕ агенту. Он нужен ТЕБЕ.** Агент - просто инструмент, чтобы извлечь из головы то, что годами копилось.

#### Notion vs business/ - главное возражение

«У меня же есть Notion. Чем это отличается?»

| Notion / Google Docs | Папка `business/` |
|---|---|
| ИИ туда не заглядывает | ИИ читает каждый раз |
| Копируешь руками | Подгружается само |
| Красивые заметки для себя | Рабочий инструмент ИИ |
| Живёт отдельно от кода | Живёт рядом с кодом |
| История через версии Notion | История через git |

Файлы в `business/` не просто справочник - они становятся **правилами**, на которые ИИ опирается перед каждым действием (через `CLAUDE.md` и `settings.json`). Через месяц в `business/` накапливается своя «конституция»: правила бренда, ограничения по UI, формулировки оффера, словарь стоп-слов. ИИ не может сделать иначе.

#### Что класть в `business/`, что НЕ класть

**Можно класть:**
- Описание продукта, тарифы, цены - то, что и так на лендинге.
- Аватары, боли, сегменты аудитории - без имён конкретных клиентов.
- Агрегированные цифры экономики (выручка за месяц, средний чек, конверсии).
- Цели, маркетинговую стратегию, конкурентов.
- Голос бренда, копи-банк, тон.

**НЕ класть:**
- Персональные данные клиентов (имена, телефоны, email, паспортные данные). Если нужно - складывай в `raw/` локально и не коммить в git, а лучше работай через API с обезличиванием.
- Чужие токены, ключи, пароли, доступы к чужим аккаунтам.
- Информацию по «серым» схемам - всё, что ты не хотел бы видеть на стороне Anthropic.

**Принцип:** «белый бизнес - спокойно. Серые схемы или ПДн - оборачивай через API/прокси с обезличиванием на твоей стороне». Anthropic данные не продаёт, но риск утечки или запроса от регулятора - реален.

**Шаг 4.5. Как поддерживать `business/` живым**

**Шаг 4.6. Кейсы — что даёт живой `business/`**

**Кейс 1 - 500 продаж за 5 сообщений.** Когда у Артемия оставалось 500 мест на потоке и 3 недели до старта — он не сел писать новую воронку. ## Этап 5. CLAUDE.md и план-фабрика (~30 мин)

**Шаг 5.1. Создаём `CLAUDE.md` — трудовой договор агента**

`CLAUDE.md` — главный файл, который Claude **подгружает в контекстное окно при каждом старте новой задачи**. В нём — оглавление проекта, правила работы, ссылки на остальные папки. Шесть пунктов трудового договора: 1) описание проекта, 2) стек, 3) структура папок, 4) роутинг «вопрос → файл», 5) правила, 6) язык.

> «Это карта офиса для нового сотрудника. Открыл новый чат — пришёл новенький, ничего не знает. Дал ему карту — стал понимать, куда бежать».

Жёсткое ограничение: **не больше 200 строк**. Иначе сжигаешь токены при каждом запуске.

**`/init` vs наш шаблон.** Команда `/init` создаст `CLAUDE.md` автоматически — но он будет банальный, минимальный, «как у всех». Туда не попадут `ai-clone/`, `mastery/`, `business/`, правила про план/рефлексию/feedback, безопасность. Поэтому: сначала `/init` (он создаст файл и поймёт стек), потом сразу **поверх него** накатываешь наш шаблон.

В самом низу оригинальной инструкции лежит готовый шаблон **«Шаблон CLAUDE.md»**. Скопируй его целиком и вставь в этот промт вместо метки `[ВСТАВЬ ШАБЛОН ЦЕЛИКОМ]`:

```
Создай в корне проекта файл CLAUDE.md по этому шаблону:

[ВСТАВЬ ШАБЛОН ЦЕЛИКОМ ИЗ РАЗДЕЛА «ШАБЛОН CLAUDE.md» В САМОМ НИЗУ ИНСТРУКЦИИ]

Действуй так:

1. Прочитай ai-clone/INDEX.md и business/INDEX.md, чтобы понять контекст проекта и меня как автора.
2. Заполни в шаблоне все поля в квадратных скобках [ВСТАВЬ ...] на основе того, что найдёшь в ai-clone/ и business/.
3. Если каких-то данных не хватает - задай мне уточняющие вопросы по одному с 3-4 вариантами ответа.
4. Проверь, что итоговый CLAUDE.md не больше 200 строк. Если больше - сократи воду, но НЕ удаляй разделы про план, рефлексию, AI-Clone, business, mastery.
5. Покажи мне итоговый файл и спроси, что доработать.

Всегда отвечай на русском.
```

**Что получишь:** правильно собранный `CLAUDE.md`, привязанный к твоему `ai-clone` и `business`. Claude будет читать его в начале каждого нового чата автоматически.

**Шаг 5.2. Папка `plans/` — один план = одна функция**

`plans/` — папка для технических планов реализации. Когда завтра ты скажешь «сделай мне такую-то фичу» — Claude сначала напишет план в `plans/`, разобьёт его на фазы со статусами `[ ]` / `[x]`, потом по нему пойдёт и будет отмечать сделанное.

Зачем не использовать встроенный `plan mode`? Plan mode живёт в одном контекстном окне. План на 3000 строк туда не влезет, агент забудет половину, токены сгорят. А внешний файл `plans/<имя-функции>.md` живёт вечно, его может подхватить любой агент в любой момент.

> «Я в одном чате формирую план, во втором чате этот план разбиваю на фазы, в третьем чате каждую фазу проверяю на адекватность. Так получается план на 3000 строк, который реально работает. А не "написал-забыл"».

Промт:
```
Создай в корне моего проекта папку plans/. Внутри создай файл README.md, в котором коротко (15-20 строк) опиши:

1. Что такое папка plans/ - место для технических планов реализации функций.
2. Правило: один план = одна функция. Если план уже есть - работаем с ним.

После создания покажи дерево корня проекта (CLAUDE.md, ai-clone/, business/, mastery/, plans/), чтобы я убедился, что всё на месте.
```

**Шаг 5.4. Критика плана — ключевая фишка методологии**

Любой план, который написал Claude с первого раза — сырой. Цикл, который работает: один чат пишет первичный план, второй разбивает на фазы, третий проверяет каждую фазу. Только после этого — реализация. Артемий так собирал план на 3000 строк, 30-50 фаз — каждая прошла критику. Без этого `plan mode` в одном окне переполняется и теряет половину.

Первый план появится завтра на Дне 3. Когда дойдёшь — прогоняй его через эти три промта в трёх разных чатах.

**Чат 1 — первичный план:**
```
@instructions.md

Прочитай мою идею. Задай вопросы, пока не уверен на 95%. После того как уверен - напиши первичный план реализации в plans/YYYY-MM-DD-название.md.

В плане: цель, гипотезы, технические решения, последовательность.

Всегда отвечай на русском.
```

**Чат 2 — разбиение на фазы:**
```
У меня есть первичный план: plans/YYYY-MM-DD-название.md.

Разбей его на фазы. Каждая фаза - конкретный результат. У каждой статус [ ] / [x]. В конце плана - итоговый блок.

После разбиения покажи мне план целиком.
```

**Чат 3 — критика каждой фазы:**
```
У меня есть план: plans/YYYY-MM-DD-название.md.

Прочитай ai-clone/INDEX.md и business/INDEX.md, чтобы понять контекст. Затем по КАЖДОЙ фазе:

1. Просканируй интернет: кто решал такую проблему, как они её решали, что мы пропускаем.
2. Проверь техническую реализуемость и риски.
3. Проверь на конфликты с другими фазами.
4. Проверь на безопасность (что может пойти не так в проде).
5. Проверь соответствие бизнес-целям из business/.

Собери выводы в один отчёт с конкретными правками. Покажи отчёт. Я скажу, какие правки принять. Обнови файл плана.

Всегда отвечай на русском.
```

> Почему работает: один агент в одном чате не может посмотреть на свою работу со стороны. Три разных чата (или три параллельных субагента) — это и есть «взгляд со стороны», который ловит 80% проблем до того, как ты начал кодить.

## Этап 6. Контекст-инжиниринг (~20 мин)

Промт-инжиниринг закончился. Сейчас в моде - **контекст-инжиниринг**: ты не пишешь длинные промты с шаблонами, ты раскладываешь файлы так, чтобы Claude **сам выбирал** правильные под задачу.

Термин ввёл Андрей Карпатый - сооснователь OpenAI, один из ключевых людей в современном AI. «Был раньше промпт-инжиниринг, теперь контекст-инжиниринг, это главнее».

**Эволюция за 3 года:**
- **2023.** Промты. «Напиши пост в стиле X, длиной Y».
- **2024.** Золотые промты. Многосоставные конструкции, шаблоны, библиотеки.
- **2026 (сейчас).** Контекст-инжиниринг. Промт короткий. Контекст в файлах. ИИ сам выбирает.

> «Не вопрос как написать промт. Вопрос - как устроить файлы, чтобы промт стал не нужен».

---

**Шаг 6.1. 5 слоёв контекста, которые Claude видит в каждом новом окне**

1. **`CLAUDE.md`** - правила проекта, навигация.
2. **`ai-clone/`** - кто ты, как думаешь.
3. **`mastery/`** - экспертная линза под задачу.
4. **`business/`** - что мы делаем, наша экономика, аудитория.
5. **История диалога** - текущий разговор.

> «Когда ты открываешь новое окно - у тебя уже под капотом всё, что тебе надо».

---

**Шаг 6.2. Что значит «правильный контекст»**

Не «ИИ знает всё». А **«берёт только то, что надо под задачу»**. Запрос «что у нас по выручке?» - Claude сам собирает: `ai-clone/principles/business.md` (как ты смотришь на деньги) -> `mastery/financial-analysis/` (метод эксперта) -> `business/economics/revenue.md` (данные) -> `business/goals/quarterly.md` (цели) -> `CLAUDE.md` -> LIVE-маркер -> SQL (свежие цифры). Возвращает разбор через линзу эксперта: не «просели заявки», а «юнит-экономика дрейфует, поднимай LTV».

**Сколько вообще влезает.** 1 токен примерно 0.75 английского слова примерно 4 русских символа. 200К токенов (Sonnet) примерно 800К русских букв. 1М токенов (Opus) примерно 4 млн русских букв в голове разом. Этого хватает на всё, что ты делаешь за день - **если** контекст устроен правильно.

**Зоны заполнения.** Команда `/context` показывает процент заполнения. До 60% - зелёная, работает идеально. 60-70% - жёлтая, пора `/compact`. 70%+ - красная, агент тупит, путается. **Третий способ** (помимо `/compact` и `/clear`) - попроси:
```
Слушай, я хочу продолжить в соседнем чате. Напиши мне промт полностью, в котором соседний чат продолжит твою задачу, не потеряв смысл.
```
Копируешь - открываешь новый чат - вставляешь. Контекст чистый, задача жива.

## Этап 7. Промтинг и работа с агентом (~30 мин)

Здесь собираем в одну мантру: **6 шагов** от идеи до результата, **цикл реализации крупной фичи** через `bulletproof`, **6 правил выживания** и **«10 причин обосраться»**.

**Шаг 7.1. 6 шагов вайб-кодинга - детально**

Уже встречалось в карте инструкции. Здесь - что делать на каждом шаге.

**Шаг 1. Инструкция (`instructions.md`).** Открываешь файл, пишешь или диктуешь голосом через `/voice`. Просто человеческим языком: что хочешь, для кого, зачем. Brain dump за 2 минуты = готовое ТЗ. Не пытайся писать «технически» - чем естественнее, тем лучше.

**Шаг 2. Уточняющие вопросы в Plan Mode.** Переключи Claude в Plan Mode (`Shift+Tab` или команда `/plan`). Промт:

```
Прочитай инструкцию. Задавай мне вопросы по одному, пока не уверен на 95% во всех деталях. Если я скажу «на твоё усмотрение» - принимай решение сам и объясняй, почему так.
```

Claude задаёт 10-20 вопросов один за другим. Отвечаешь голосом. На вопросы, в которых не разбираешься - «на твоё усмотрение».

**Шаг 3. Создание `CLAUDE.md`.** Claude собирает стек, дизайн-систему (цвета, шрифты, скругления), структуру файлов, соглашения. Проверяешь файл целиком, поправляешь то, что не понравилось. Это базовый промт-договор для всего проекта.

**Шаг 6. Чанки для больших фич.** Если фича большая (день и больше работы) - разбей план на блоки. Каждый блок = отдельный диалог. Контекст не переполняется, фокус сохраняется.

> «На шаге 4 - новый диалог. Критично. Иначе контекст разогрева подаст ошибки в реализацию».

**Шаг 7.2. Цикл реализации крупной фичи**

6 шагов выше - базовый процесс. Для крупных фич (день и больше работы) поверх работает 12-этапный цикл: Deep Research → Spec → План + Критика → Фазы реализации → Тесты → Security Review → поиск ошибок → доводка → деплой. На фичу обычно уходит 10 из 12 этапов, на архитектурное изменение - все 12, на багфикс - 6. **Research → Spec → Plan → Critique - до кода.** Ошибка на плане = 1 минута. Ошибка в коде = день переписки.

Запуск - через скилл `bulletproof` (см. Этап 8). Триггер - фраза «давай сделаем большую фичу».

**Шаг 7.3. Хороший vs плохой промт**

| Плохой | Хороший |
|---|---|
| «Сделай сайт для выгула собак» | «Лендинг Happy Paws. Hero. 3 услуги с ценами. Форма. Синяя схема.» |
| Результат: генеричный, безликий | Результат: конкретный, структурированный |

4 ускорителя промптинга:
1. Начинай в Plan Mode - пусть Claude сначала спланирует.
2. Говори: «задай вопросы, пока не уверен на 95%».
3. Конкретно, но не перегружай. Голос быстрее печати в 3 раза.
4. **Скриншот-референс > 500 слов описания.** Перетащил скриншот - сказал «как здесь, но с нашими цветами».

**Шаг 7.4. Скриншоты в буфер - ускоритель работы в 3-4 раза**

Перенастрой скриншот так, чтобы он сразу попадал в буфер обмена, а не на рабочий стол. Тогда копируешь в чат Claude через `Ctrl+V` за секунду.

**Mac:**

- Выделил область - сразу в буфере

**Шаг 7.5. To-do list + скриншот-цикл - контроль качества**

Когда Claude собирает большую фичу, он сам строит to-do list с галочками. Усиление - попроси:

Скриншот-цикл - когда Claude смотрит на результат своими глазами:

> Будь искренне любопытен: «что ты сделал?». За неделю поймёшь 80% того, что Claude делает.

**Шаг 7.6. 6 правил выживания (мантра)**

Выучи как таблицу умножения. Это разница между «бьюсь 5 часов» и «делаю за 30 минут».

1. **Один чат = одна задача.** Закончил -> закрой чат -> открой новый. Очищает контекст и твою «оперативку». Каждое следующее сообщение в этом же чате тянет всю историю - токены улетают.
2. **Контекст <= 60%.** Больше - `/compact` или `/clear`. Третий способ - попроси «напиши промт, в котором соседний чат продолжит эту задачу, не потеряв смысл». Копируешь - открываешь новый чат - вставляешь.
3. **Ничего не делай руками.** Папки, файлы, команды в терминале - всё через Claude. Желание «я сам быстрее» - бей по рукам.
4. **Ошибки чини в том же чате,** где писал функцию. Не открывай новый - потеряешь контекст. Если контекст переполнен - попроси «напиши промт с этой ошибкой, детально объясни, ничего не упусти», и переходи в новый чат с этим промтом.
5. **Долго думает (5-10 минут) - не перезапускай.** Подожди. Если совсем висит дольше часа - нажми «стоп», просто напиши «далее». Если совсем не помогает - `/clear` и переформулируй короче.
6. **Каждая большая функция = план в `plans/`** + рефлексия в `retrospectives/`. Уже зашито в CLAUDE.md, агент будет делать сам.

---

**Шаг 7.7. «10 причин обосраться» - убийственный промт**

Любимый стресс-тест Артемия. Запускается перед каждым крупным шагом: перед эфиром, перед деплоем, перед запуском продаж. Находит дыры, которых сам не видишь.

Прямо сейчас прогони через него свой `CLAUDE.md` + `business/` + `ai-clone/` - пусть Claude найдёт слабые места ещё до того, как ты начал собирать сайт на Дне 3:

Промт:
```
У меня есть CLAUDE.md, папка ai-clone/, папка business/, папка mastery/. Завтра я буду собирать по этому каркасу свой проект.

Твоя задача - стресс-тест. Найди 10 причин, из-за которых мы обосрёмся:

- где в CLAUDE.md двусмысленности, которые ты как агент можешь понять неправильно
- где в business/ пробелы, из-за которых решения придётся выдумывать
- где в ai-clone/ нет важной информации обо мне (тон, принципы, ценности)
- где бизнес-логика противоречит сама себе
- где стек или принципы противоречат реальности моей идеи
- где я переоцениваю объём одного дня
- где я недооцениваю объём (а это даже хуже, потому что не закладываешь время на ключевое)

Не стесняйся. Критикуй жёстко. Я хочу найти эти 10 причин сейчас, а не в проде.

В конце дай список конкретных правок: что и в каком файле исправить, чтобы этих причин не было.
```

Прими те правки, которые согласуешься, попроси Claude внести их в нужные файлы. Сэкономишь часы на Дне 3.

> Этот же промт применяй к любому крупному решению: план фичи, оффер на лендинге, схема воронки, схема деплоя. Любой «большой текст» можно стресс-тестить через «10 причин».

**Шаг 7.8. Модели Claude: Opus / Sonnet / Haiku**

Внутри Claude Code три модели, у каждой своя роль:

| Модель | Роль | Когда |
|---|---|---|
| **Opus** | Архитектор | Планирование, сложные решения. До 1M контекста примерно 4 млн русских букв в голове разом. |
| **Sonnet** | Исполнитель | Реализация, правки, код. 200K контекста примерно 800K русских букв. |
| **Haiku** | Быстрый | Рутина, обработка больших объёмов. |

Переключение - `/model`. Лайфхак: `/model → "opus plan"` - Claude сам выбирает Opus для планирования и Sonnet для реализации. Для глубокого мышления добавляй `Thinking Max` или `ultrathink`. Версии моделей обновляются раз в пару месяцев (на момент эфира Opus был уже 4.7) - не зацикливайся на цифре.

## Этап 8. Скиллы Claude Code (~30 мин)

**Скилл = упакованный промт + опциональные скрипты.** Узкая экспертиза в одной задаче. Claude подтягивает скилл сам, когда видит подходящий триггер. Прогрессивная загрузка: имя + описание скилла висит в контексте за ~100 токенов; полный `skill.md` загружается только когда скилл реально нужен. Даже 50 установленных скиллов жрут ~5K токенов из 200K окна.

**Аналогия:** без скиллов Claude - стажёр общего профиля, повар без рецепта. Со скиллами - команда экспертов под рукой, повар с рецептами от шеф-поваров.

**Где живут.** Глобальные - в `~/.claude/skills/` (доступны во всех проектах). Локальные - в `.claude/skills/` в корне проекта. Базовые от Anthropic (Frontend Design, Skill Creator, PDF, PPTX) и `bulletproof` - ставь **глобально**.

**Как вызвать.** Слэш-команда (`/pdf`, `/frontend-design`) или естественный язык («создай PDF-отчёт» - Claude сам найдёт).

**Где брать:**

| Источник | Что там |
|---|---|
| `smithery.ai` | Маркетплейс по категориям: research, design, code |
| Anthropic | Frontend Design, Skill Creator, PDF, XLSX, PPTX, Memory, Computer Use |

**$100/мес ≈ команда из 5 специалистов.** Подписка Claude Max - $100/мес. Внутри: дизайнер, верстальщик, копирайтер, аналитик, генератор презентаций и PDF. Рынок: фронтенд-разработчик 150-300К ₽, дизайнер 150-300К ₽, копирайтер 80-200К ₽, аналитик 100-250К ₽. Итого 500К+ ₽/мес. За $100 (≈ 9-10К ₽) - всё то же самое, 24/7. Через год: 30-50 скиллов = команда из 30 специалистов.

**Безопасность скиллов.** Скилл - исполняемая инструкция от автора. Прокидывать туда чужой код без аудита = сдать ключи от квартиры незнакомцу. Плохой скилл может прочитать `.env`, отправить ключи через `curl`, удалить файлы. Перед установкой смотри звёзды на GitHub, автора, прогоняй через промт-аудит:

```
Я хочу установить скилл по ссылке [ВСТАВЬ URL РЕПОЗИТОРИЯ]. Скачай исходники, прочитай README.md, SKILL.md и все .md/.sh файлы. Проверь, нет ли опасных операций:

- чтения .env или других файлов с секретами
- отправки данных на внешние URL (curl, wget, fetch)
- удаления файлов (rm, unlink)
- запуска внешних бинарников
- подмены существующих файлов проекта

Дай вердикт: безопасно / подозрительно / опасно. Если опасно - НЕ ставь.
```

**Шаг 8.1. Bulletproof - авторский скилл Артемия**

Bulletproof - 12-этапный воркфлоу от ресёрча до деплоя. Превращает большую задачу в управляемый конвейер: research -> spec -> план + критика -> фазы реализации -> тесты -> security review -> поиск ошибок -> доводка -> деплой. Не каждая задача проходит все 12: багфикс - 6, фича - 10, изменение архитектуры - все 12. Триггерится по фразе **«давай сделаем большую фичу»** или «прогоним через bulletproof».

Сначала аудит (промт выше), потом установка глобально:

```
Установи скилл bulletproof по ссылке https://github.com/artemiimillier/bulletproof ГЛОБАЛЬНО (~/.claude/skills/), чтобы он был доступен во всех моих проектах.

Конкретно:
1. Положи скилл в ~/.claude/skills/bulletproof/.
2. После установки покажи структуру и расскажи, как им пользоваться: какие фазы, какие триггеры, как запустить воркфлоу.
3. Скажи, по каким фразам Claude сам поймёт, что пора активировать bulletproof.

Если у тебя есть встроенная команда установки скиллов - используй её. Если нет - клонируй репозиторий вручную.
```

```
Установи skill-creator от Anthropic ГЛОБАЛЬНО в ~/.claude/skills/.
```

```
5. Вывести его в консоль

Задай мне уточняющие вопросы по одному. После создания - протестируй скилл прямо здесь.
```

## Этап 9. MCP, плагины, CLI (~15 мин)

Иерархия по жадности к токенам: **скилл (~100 токенов поиска) -> MCP (~2000+ токенов всегда) -> CLI (0 токенов)**. Это важно понять, чтобы не подключать всё подряд.

---

**MCP - USB-порт для сервисов**

MCP (Model Context Protocol) - стандартизированный способ подключить Claude к любому внешнему сервису: Google Sheets, Gmail, Notion, CRM, твоему API, базе данных, браузеру.

> «MCP - это USB-порт для сервисов. Раньше каждый API писали кастомно. Сейчас единый протокол, Claude подключается одинаково ко всему».

**Полезные MCP, которые ставят чаще всего:**

| MCP | Что даёт |
|---|---|
| **Google Sheets** | 38 инструментов. Таблицы целиком: читать, писать, формулы. |
| **Chrome DevTools** | Кликать, заполнять формы, парсить, делать скриншоты прямо в браузере. |
| **Firecrawl** | Продвинутый парсинг сайтов с обходом блокировок. |
| **Context7** | Актуальная документация любой библиотеки за один запрос. |

Установка: `smithery.ai` -> копируешь промт -> вставляешь в Claude Code, остальное он делает сам.

**Внимание:** каждый MCP жрёт ~2000 токенов в контексте при каждом сообщении (потому что описание ВСЕХ его инструментов всегда висит). 10 MCP установил = 20 000 токенов сгорают на каждый запрос, даже если ты ими сейчас не пользуешься.

> «10 MCP = 20 000 токенов на каждый запрос. Не подключай на всякий случай».

| | MCP | Скилл |
|---|---|---|
| Загрузка | ВСЕГДА (при каждом сообщении) | По запросу (только когда триггер) |
| Контекст | ~2000+ токенов | ~100 токенов на поиск |
| Когда выгодно | Частое использование | Редкое использование |

**Лайфхак Артемия:** **«Сделай скилл из MCP Google Sheets, чтобы отключить MCP»**. Получается огромная экономия контекста: 2000 -> 100 токенов. Используешь редко - превращай в скилл.

Как использовать:

1. Если нужно работать с каким-то сервисом - спроси Claude:

```
Есть ли MCP-сервер для [название сервиса, например Google Sheets]? Если да - дай ссылку и команду установки локально в этот проект. Если нет - есть ли у этого сервиса открытое API? Если да - прочитай документацию и предложи скрипт-адаптер.
```

2. Если MCP есть - ставишь через тот же двойной цикл аудит -> установка.
3. Если только API - Claude напишет тебе скрипт под твой проект.

---

**Плагины**

Плагины - расширения самой среды Claude Code (новые команды, интеграции). Управление - `/plugins`. Различие: **скилл = инструкция, MCP = сервис, плагин = возможность среды**.

---

**CLI - третья ветка (нулевая нагрузка на контекст)**

CLI (command line tools) - терминальные программы, которые делают конкретную работу. **Нулевая нагрузка на контекст** - запускаются и завершаются, токены не жрут вообще. Примеры open-source инструментов с GitHub: `ffmpeg` для видео/аудио, `LiveKit` для видеозвонков, готовые парсеры YouTube/Дзена. Чужой open source решает задачу за пару минут установки - не пиши свой парсер с нуля.

```
У меня задача: [описание, например «надо из аудиофайла .m4a сделать транскрипцию» или «парсить страницы Дзена на содержание»].

Поищи open-source CLI-инструменты, которые это решают. Найди топ-3 на GitHub. Сравни по звёздам, активности, лицензии. Лучший: покажи установку и однострочный вызов. Не пиши свой парсер, если open-source уже есть.
```

> «Зачем писать парсер с нуля, если кто-то уже его написал и бесплатно раздаёт?»

## Этап 10. Браузерный Claude (Claude Chrome) (~10 мин)

Расширение для Google Chrome от Anthropic. AI сам кликает по сайтам, заполняет формы, выгружает данные - как живой пользователь. Кейсы: создать сервер в Яндекс.Облаке без открытия вкладок, настроить CRM, выгрузить отчёт из закрытой системы, написать статью на Дзене за тебя. Рекомендую пользоваться всегда, где есть рутина в браузере.

Два режима: **«Ask before doing»** (спрашивает перед каждым действием - начинай с этого) и **«Do without asking»** (делает сам).

```
Установи расширение Claude Chrome для Google Chrome.

1. Найди в Chrome Web Store официальное расширение от Anthropic.
2. Покажи мне ссылку на установку.
3. Объясни, как авторизоваться через мой аккаунт Claude.
4. Объясни разницу между режимами «спрашивать перед действием» и «действовать без спроса». Рекомендуй начать с «спрашивать».

После установки сделай маленький проверочный прогон: открой google.com, попроси его сделать поиск «погода Москва», сделай скриншот результата.
```

> Фишка: попроси Claude Code написать промт для браузерного агента - он напишет, ты вставишь в Chrome-Claude, всё сделается само.

**Концептуально: субагенты, деплой, Claude на телефоне (всё на Дне 3)**

Технически собирать сегодня не нужно - всё будет на Дне 3. Сейчас - понимай, что это есть.

**Субагенты.** Вспомогательные агенты, которых главный Claude запускает на отдельные задачи. Каждый - в своём контексте, со своей моделью: **Opus** для анализа, **Sonnet** для кода, **Haiku** для рутины. Живут в `.claude/agents/`. Зачем: экономия контекста (50К токенов файла → выжимка на 500 токенов в главный чат) и параллельность (5 субагентов одновременно).

**Оркестратор параллельных агентов.** Когда план разбит на фазы: сначала 1 блокирующая фаза → потом 3-5 параллельных → финальная сборка. **Главное правило:** два агента, правящие один файл, сломают друг друга. Параллелить можно только непересекающиеся фазы. Ускорение в 3-5 раз.

**Деплой.** Claude Code → GitHub → Vercel (или альтернативы: Amvera, Railway) → сайт в интернете. ~30 секунд от изменения до live. Подробно - на Дне 3.

**Claude на телефоне.** Приложение Claude (iOS / Android, Remote Control - сканируешь QR-код) или Telegram-бот через @BotFather + плагин. В дороге, в очереди, в постели - команда, и Claude её выполнит.
