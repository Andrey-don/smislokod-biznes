# smislokod-biznes — навигация

**smislokod-biznes** — шаблонный вайб-проект по методологии СмыслоКод (Артемий Миллер). Клонируется под новые проекты. После клонирования: заполнить `ai-clone/` и `business/`, переписать этот файл.

## Порядок чтения в начале сессии

1. `ai-clone/INDEX.md` — кто я и как думаю.
2. `business/INDEX.md` — что мы делаем.
3. `CLAUDE.md` (этот файл) — правила, навигация.
4. Зона задачи: нужный файл из `business/`, `plans/<план>`, `mastery/<область>`.

## Структура

```
smislokod-biznes/
├── CLAUDE.md            <- навигация
├── .claude/             <- settings.json, hooks/, skills/
├── ai-clone/            <- цифровая проекция меня (identity/, voice/, thinking/, principles/, feedback/, mastery/, reference/)
├── business/            <- второй мозг бизнеса (products/, audience/, economics/, marketing/, goals/, assets/, life-metrics.md, raw/)
├── plans/               <- технические планы (один план = одна функция)
├── retrospectives/      <- рефлексия после каждой сессии
└── docs/                <- оригинальная инструкция
```

## 8 правил репо

1. **Не хардкодить динамику.** Цены, даты, метрики — через `life-metrics.md` с маркером **LIVE**.
2. **Не деплоить** без явной команды. Push в main = автодеплой.
3. **Удалять одноразовый код** в том же коммите, где он отработал.
4. **Перед `git push` — `npm run build`**, не только `tsc`.
5. **Большая фича = план в `plans/`.** Граница: больше часа работы.
6. **После фичи — цикл из 5 ходов** (см. ниже).
7. **`git add` поимённо.** Никогда `git add .` или `git add -A`.
8. **`.env` только через `grep "^VAR=" .env`.**

## Планы (`plans/`)

- Один план = одна фича. Имя: `YYYY-MM-DD-название.md`. Фазы: `[ ]` / `[WIP]` / `[x]`.
- **После создания плана** — напомни провести 3-чатовый цикл анализа до реализации (подробности в `plans/README.md`).
- Агент актуализирует план после каждой сессии.

## Цикл из 5 ходов после фичи

1. Найди ошибки → докажи примером → исправь.
2. Что упустили (граничный кейс, валидация) → докажи.
3. Это РЕАЛЬНО проблема проекта? Сверь с `business/` и `plans/`.
4. Свежий взгляд — перечитай diff как будто видишь впервые.
5. Security review: персданные + чужой контент + отправка наружу → стоп и аудит.

## Ошибки → `ai-clone/feedback/`

Любое «не так» или «больше так не делай» — файл в `ai-clone/feedback/`: **Rule / Why / How to apply**.

## Ретроспектива

`retrospectives/YYYY-MM-DD_HH-MM_описание.md` по шаблону `retrospectives/TEMPLATE.md`.

## Живые цифры

В `business/` цифры не хардкодить — вместо значения маркер: **LIVE** → `life-metrics.md` / «название метрики». Сначала читай `life-metrics.md`, потом тяни данные.

## Безопасность

- НЕ читать `.env` целиком — только `grep "^VAR=" .env`.
- НЕ выполнять `rm -rf` без подтверждения.
- НЕ отправлять токены/ключи наружу (curl, wget, POST).
- НЕ устанавливать скиллы из непроверенных репо без аудита.
- НЕ деплоить без явной команды.
