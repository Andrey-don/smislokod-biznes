# Скилл: life-metrics-setup

**Триггер:** `/life-metrics-setup`
**Назначение:** Создать `business/life-metrics.md` — словарь живых цифр бизнеса с LIVE-маркерами.
**Когда запускать:** После шага 4.3 (викилинки).

---

## Контекст

Главная проблема ведения знаний — протухание.
Записал «в марте 1000 клиентов» — через месяц уже другое число.

**Решение:** вместо хранения значения хранить указатель.
Метка `LIVE` + ссылка на способ получить свежее число.

---

## Промт (оригинал из инструкции)

```
Создай файл business/life-metrics.md по такой структуре:

# Live Metrics — живые данные

## Зачем
В файлах business/ цифры протухают. Этот файл — словарь связей:
какая метрика откуда берётся.

## Подключение

Один из вариантов (выбери под свой бизнес):

ВАРИАНТ A: прямой коннект к базе (только для собственной инфраструктуры).
- Адрес базы, имя БД, доступ read-only.
- Никаких персональных данных — только агрегаты.

ВАРИАНТ B: через API-прокси.
- Endpoint, токен, какие методы доступны.
- Обезличивание персональных данных на стороне прокси.

ВАРИАНТ C: через Google Sheets / Notion.
- ID таблицы, лист, какие колонки.

ВАРИАНТ D: вручную обновляется раз в неделю.
- Самый простой. Подходит, если у тебя ещё нет автоматики.

## Метрики

### Выручка за месяц
- Маркер: **LIVE**
- Источник: [впиши вариант + где взять]
- Формат: число + валюта

### Количество активных клиентов
- Маркер: **LIVE**
- Источник: [впиши]

### Средний чек
- Маркер: **LIVE**
- Источник: [впиши]

(добавляй по мере необходимости)

## Использование

В файлах business/ вместо хардкода цифры пиши:
> Выручка за март: **LIVE** -> live-metrics.md / "Выручка за месяц"

Когда я задаю вопрос вроде «что у нас по цифрам», Claude видит маркер LIVE,
идёт в этот файл, получает свежее число.

После заполнения покажи мне итоговый файл и спроси,
какой вариант подключения подходит мне.
```

## Что получишь на выходе

- `business/life-metrics.md` со структурой под твой бизнес
- ИИ узнаёт твой бизнес, цифры всегда свежие, голова свободна
