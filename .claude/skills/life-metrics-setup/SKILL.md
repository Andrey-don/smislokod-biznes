# Скилл: life-metrics-setup

**Триггер:** `/life-metrics-setup`
**Назначение:** Настроить `business/life-metrics.md` — подключить живые цифры бизнеса к проекту.
**Когда запускать:** После заполнения `business/` через интервью (после шага 4.2).
**Время:** ~15-30 минут (зависит от выбранного способа подключения).

---

## Промт (запускать в новом диалоге)

```
Помоги мне настроить business/life-metrics.md — файл с живыми цифрами бизнеса.

МОИ ИСТОЧНИКИ ДАННЫХ:
[ВПИШИ: откуда берёшь цифры — CRM, Google Sheets, Telegram Stats,
 эквайринг, таблица в Excel, считаешь руками и т.д.]

ШАГ 1 — Спроси меня, какие метрики я хочу отслеживать:
- Финансовые (выручка, средний чек, расходы)
- Аудитория (подписчики, охваты)
- Воронка (лиды, конверсии, CAC, LTV)
- Продукт (активные клиенты, NPS, отток)
Задавай по одному вопросу, предлагай 3-4 варианта.

ШАГ 2 — Предложи мне выбрать способ подключения данных:

ВАРИАНТ А — Ручное обновление (просто, без кода):
  Я открываю файл и вписываю цифры руками раз в неделю/месяц.
  Плюс: не нужен код. Минус: надо помнить.

ВАРИАНТ Б — Google Sheets (полуавтомат):
  Таблица Google Sheets → скрипт раз в день тянет цифры → обновляет файл.
  Плюс: данные всегда свежие. Минус: нужно настроить скрипт.

ВАРИАНТ В — Прямое API (продвинутый):
  Telegram Bot API, AmoCRM API, Stripe API → скрипт забирает данные напрямую.
  Плюс: полная автоматизация. Минус: нужен разработчик или Claude Code.

ВАРИАНТ Г — MCP-интеграция (будущее):
  Claude сам ходит в источник через MCP-сервер при каждом запросе.
  Плюс: всегда актуально, без скриптов. Минус: нужен MCP-сервер.

ШАГ 3 — На основе выбранного варианта:
- Заполни business/life-metrics.md реальной структурой под мои метрики
- Добавь инструкцию по обновлению данных (для выбранного варианта)
- Если выбран вариант Б или В — напиши скрипт или план подключения

ШАГ 4 — После настройки:
- Покажи итоговый business/life-metrics.md
- Объясни: что нужно делать каждый раз, когда Claude спрашивает про цифры

ПРАВИЛО ДЛЯ CLAUDE (вшить в файл):
Когда в файле есть <!-- LIVE --> — это сигнал, что данные могут устареть.
Перед анализом спроси пользователя: «Цифры актуальны? Последнее обновление: [дата]»

Всегда отвечай на русском.
```

---

## Что получишь на выходе

- `business/life-metrics.md` заполнен реальными метриками под твой бизнес
- Инструкция по обновлению данных (для выбранного способа)
- Скрипт или план подключения (для вариантов Б/В)
- Claude знает, когда данные устарели и как об этом спросить

## Варианты подключения (кратко)

| Вариант | Усилие | Актуальность | Рекомендация |
|---|---|---|---|
| А — руками | минимум | раз в неделю | Старт, MVP |
| Б — Google Sheets | средне | ежедневно | Малый бизнес |
| В — API | высокое | в реальном времени | Масштаб |
| Г — MCP | настройка 1 раз | при каждом запросе | Будущее |
