# Скилл: business-wikilinks

**Триггер:** `/business-wikilinks`
**Назначение:** Расставить викилинки `[[файл]]` между всеми файлами `business/` — создать граф знаний.
**Когда запускать:** После заполнения `business/` через интервью (после шага 4.2).
**Время:** ~10 минут.

---

## Промт (запускать в новом диалоге)

```
Пройди по всем файлам в папке business/ и расставь викилинки [[имя-файла]]
между логически связанными документами.

ПРАВИЛА:
- Викилинк пишется как [[имя-файла]] без расширения .md
- Ставь ссылку там, где документ реально нужен для понимания контекста
- Не ставь ссылки ради ссылок — только если есть смысловая связь
- В каждом файле секция «Связанные файлы» внизу — добавь туда ссылки,
  которых ещё нет

ЛОГИКА СВЯЗЕЙ (руководствуйся этим):
- avatar.md ↔ objections.md ↔ journey.md (аудитория — одна система)
- overview.md ↔ pricing.md ↔ unit-economics.md (продукт и деньги)
- funnel.md ↔ channels.md ↔ journey.md (путь клиента)
- annual.md → quarterly.md → monthly.md (цели каскадом)
- life-metrics.md ↔ revenue.md ↔ unit-economics.md (живые цифры)
- copy-bank.md ↔ avatar.md ↔ brand-guidelines.md (голос и аудитория)
- competitors.md ↔ overview.md ↔ content.md (позиционирование)

ПОСЛЕ РАССТАНОВКИ:
1. Выведи список: какой файл → какие ссылки добавил
2. Покажи граф в виде текстовой схемы: файл → [связанные файлы]
3. Спроси, нужно ли добавить или убрать какие-то связи

Всегда отвечай на русском.
```

---

## Что получишь на выходе

- Все файлы `business/` связаны между собой через `[[викилинки]]`
- Граф знаний: Claude при работе с одним файлом знает, куда идти дальше
- Текстовая схема связей для проверки

## Почему это важно

Без викилинков каждый файл — отдельный остров. Claude читает только то, что ты явно указал.
С викилинками — он сам переходит к связанному контексту. Это делает ответы умнее.
